## 2026-10-09 - Missing PairingManager Token Validation in Standalone WebSocketHandler
**Vulnerability:** `WebSocketHandler.HandleWebSocket` in `internal/webserver/ws.go` extracted the `token` query parameter and verified its presence (`token != ""`), but failed to validate whether the token was actually approved via `PairingManager.IsApproved(token)` before creating a session (`wh.sessionManager.CreateSession("", token)`). An unauthenticated attacker could supply any non-empty dummy token (e.g. `?token=123`) to create session records and attempt terminal upgrades.
**Learning:** Handlers or helpers constructed independently from the main server struct (`ServerV2` / `Server`) must carry references to security/authentication components (like `PairingManager`) rather than relying on callers or assumption comments (e.g. `// validation of token should be done by caller`).
**Prevention:** Ensure all handlers dealing with sensitive resources or terminal connections inject and invoke explicit token/pairing validation routines prior to side effects like session creation or PTY attachment.
